# 顺序队列实战：假满、挪表与接口

## 训练目标

照着顺序队列的思路自己封装 Queue。front/rear 向后移动后，数组尾部到头不一定真的满；这次需要挪表回收前面的空位，再继续入队。

编辑器仍然从空白开始，请自己写完整程序。建议先完成基础操作，再联调，不要直接抄整份参考答案。

## 输入

第一行 capacity q，随后 q 行操作。1≤capacity≤6，1≤q≤16，元素绝对值≤100。有效区间为 [front,rear)，初始 front=rear=0。

## 操作与输出

| 操作 | 要做的事与输出 |
| --- | --- |
| `1 value` | 入队，输出 `OK` 或 `FULL` |
| `2` | 出队并输出值；空队列输出 `EMPTY` |
| `3` | 查看队头，不出队；空队列输出 `EMPTY` |
| `4` | 输出 size |
| `5` | 从队头到队尾输出序列，空队列输出 `EMPTY` |
| `6` | 清空并将 front、rear 都置 0，输出 `OK` |
| `7` | 输出 `front rear` |

不打印菜单和额外提示文字。

## 建议实现

- 定义 Queue（data、front、rear、capacity），实现 `queueinit / isempty / size / compact / q_push / q_pop / front_value / clear`。
- 只在入队遇到 rear==capacity 且还有逻辑空位时挪表；挪表之后 front=0、rear=原 size。
- 出队只增加 front，即使刚出到空，也不自动重置下标；这样操作 7 可以验证状态。
- pop 和 peek 使用成功标志与输出指针区分失败和数值 0。

## 分步提示

真正满的条件是 rear-front==capacity。compact 先保存原 front，把剩余元素向前搬，再更新两个下标。不要让查看队头改变 front。
