# 栈实战：有容量限制的完整 ADT

## 训练目标

把栈封装到结构体里，自己实现初始化、判空、压栈、弹栈、查看、清空和遍历。遇到满栈或空栈时要返回失败，而不是假装操作成功。

编辑器仍然从空白开始，请自己写完整程序。建议先完成基础操作，再联调命令，不要直接抄整份参考答案。

## 输入

第一行 capacity q，随后 q 行操作。1≤capacity≤6，1≤q≤16，元素绝对值≤100。top 表示栈顶下标，空栈 top=-1。

## 操作与输出

| 操作 | 要做的事与输出 |
| --- | --- |
| `1 value` | 压栈；输出 `OK` 或 `FULL` |
| `2` | 弹栈并输出值；空栈输出 `EMPTY` |
| `3` | 输出栈顶但不弹出；空栈输出 `EMPTY` |
| `4` | 输出 size |
| `5` | 清空，输出 `OK` |
| `6` | 从栈底到栈顶输出，空栈输出 `EMPTY` |

所有查询或状态输出各占一行，不打印菜单和额外提示文字。

## 建议实现

- 定义 Stack（data、top、capacity），操作函数接收 `Stack *s`。
- 实现 `initStack / isEmpty / push / pop / peek / size / clear`。
- pop 和 peek 用 `int *e` 返回数据，函数返回值只表示成功或失败。
- FULL、EMPTY 都不能改变 top；peek 不允许修改状态。

## 分步提示

先检查边界，再改变 top。不要把弹出的 0 当作失败，因为 0 可以合法入栈。把提示输出集中放在 main，避免数据结构函数打印额外内容。

## 样例

输入：
```text
3 11
1 2
1 0
1 5
1 9
3
2
4
6
2
2
2
```

输出：
```text
OK
OK
OK
FULL
5
5
2
2 0
0
2
EMPTY
```

## 写完后自查

连续 peek 两次之后 size 是否相同？满栈继续 push 后，原栈顶是否保留？清空后是否能再次压栈？

只运行 3 个小用例，每例限时 2 秒，不增加大规模或极端输入。难度来自完整结构、多操作联调和普通边界处理，而不是输入规模。运行样例不计完成，提交全部通过才完成环节。
